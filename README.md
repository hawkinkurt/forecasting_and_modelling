# Forecasting and Modelling

Monitoring tools and forecasting models for the UK and US economies.

## What's here

- **Real-time data store.** Official statistics are pulled from the ONS and the Bank of England into a DuckDB database. Every release is kept as a separate vintage, so models can be tested on the data that was actually available at the time, not today's revised figures.
- **A daily monitoring run** that fetches every tracked series, stores only new or revised values, logs each fetch and emails a "what changed" report: new releases with trend lines, market moves, revisions to recent data, releases due in the next week and any data problems.
- **A Power BI dashboard defined as code.** The report is a Power BI Project (`.pbip`), stored as text and generated by a Python script, so the data model, DAX measures and every page are version controlled and reproducible.
- **Forecasting models** (in progress), with every forecast stored so its accuracy can be tracked against outturns.

## How the pipeline works

```
series.csv → registry → fetchers (ONS, BoE) → vintage-aware store → SQL views → Parquet → Power BI
                                   └→ fetch log            └→ "what changed" report
```

1. **Registry.** `series.csv` lists every tracked series with its source code, frequency, units and section.
2. **Fetchers.** One module per data source, each returning the same shape: periods, values and the publication (vintage) date.
3. **Store.** Only new periods and revised values are written. A revision becomes a new row with a later vintage, so history is never overwritten.
4. **Fetch log.** Every series on every run is logged as `ok`, `no change` or `error`. One failure does not stop the run.
5. **Views and exports.** SQL views derive everything else from the stored data: growth rates (period, y/y, 3-month-on-3-month annualised), real pay, yield curve spreads, the real policy rate, fiscal-year-to-date borrowing, data revisions and a data health check. `export.py` writes them to Parquet for Power BI. Derived growth rates are checked against the ONS's own published figures.

## Layout

| Path | Purpose |
|---|---|
| `series.csv` | The list of tracked series |
| `run.py` | Runs the whole pipeline |
| `pipeline/` | Registry, storage, console and email reports, source fetchers |
| `sql/schema.sql` | Tables: series registry, vintaged observations, fetch log, forecasts |
| `sql/views.sql` | Derived measures: growth rates, real pay, yield curve, fiscal year borrowing, revisions, data health |
| `export.py` | Writes Parquet files to `exports/` for Power BI |
| `setup_db.py` | Creates or updates the database on its own |
| `powerbi/build_pbip.py` | Generates the Power BI project: star-schema model, DAX measures and report pages |
| `powerbi/UK Macro Monitor.pbip` | The dashboard. Open in Power BI Desktop and press Refresh |

## The dashboard

Seven pages: an overview of every series with headline cards, then activity, the labour market (including real pay), inflation against the 2% target, rates and money (gilt yields, yield curve spreads, the real policy rate, mortgages), public finances and the external sector (fiscal-year-to-date borrowing against last year, trade, sterling), and a data health page fed by the pipeline's fetch log.

The model is a star schema: a `Series` dimension and a calculated `Date` table filter the fact tables built from the Parquet exports. To regenerate it after changing the script, close Power BI Desktop and run:

```powershell
.\.venv\Scripts\python powerbi\build_pbip.py
```

The `ExportFolder` parameter points at the local `exports/` folder. After cloning, change it in Power BI (Transform data → Manage parameters) or edit the path at the top of `powerbi/build_pbip.py`.

## Running it

```powershell
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
.\.venv\Scripts\python run.py
```

To receive the email report, copy `.env.example` to `.env` and fill in a Gmail address and a Gmail app password. Without them the run still works and saves the report to `exports/last_report.html`. Use `run.py --no-email` to skip sending.

The database (`data/`) and exports (`exports/`) are rebuilt by the pipeline and are not stored in the repository.
